# بنك الأسئلة والدفعات الجديدة

الفئات: الأطفال حتى 12 سنة شاملًا، والكبار من 13 سنة. المستوى 1 سهل، 2 متوسط، 3 صعب. هذه تقديرات تحريرية للمحتوى والخيارات، وليست نتائج قياس على لاعبين. كل سؤال منشور له مستوى صريح؛ عدد الصفوف أو ترتيبها لا يحدّد الصعوبة. لا نساوي أعداد الأسئلة بين المستويات على حساب جودتها.

## دفعة 22 أكتوبر 2026

اعتمد المستخدم النسخة الحالية ذات الورقة الواحدة والأسئلة الـ21 فقط. لم تُضف أسئلة الورقة المحذوفة. القراءة المعتمدة محفوظة في `hard_questions_source_2026-10-22.json`.

المصدر `Castle_Heroes_Hard_Questions.xlsx`: 21 سؤالًا للكبار بمستوى 3. أُضيفت أولًا 19 منها، ثم اكتمل السؤالان المتبقيان بعد تزويد المستخدم رابطَي صورتي رونالدينيو وكاكا. الصور محفوظة في `assets/question_photos` ومضمّنة بالمحلي والأونلاين، بارتفاع 180 بدل ارتفاع الأعلام 75. المعرفان 280 و281. ذُكر القميص الظاهر في صياغة كل سؤال لتمييزهما دون كشف اسم اللاعب ومنع إخفاء أحدهما باعتباره تكرارًا للنص نفسه. بقية أسئلة الدفعة مستقلة عن صور المصدر الاختيارية.

## إضافة دفعة لاحقة

اكتملت بعد دفعة Excel دفعة أصلية موثقة من 60 سؤالًا: 30 للأطفال و30 للكبار. نصفها للدين والقرآن، دون أسئلة دينية سهلة أو اعتماد روايات خلافية؛ والباقي علوم وتاريخ وجغرافيا وحساب ومنطق. المرجع والشرح محفوظان لكل سؤال في ملفي `verified_60_2026-10-22_children.json` و`verified_60_2026-10-22_adults.json` تحت `data/imports`. قائمة كاملة قابلة للمراجعة في [QUESTION_BATCH_2026-10-22.md](QUESTION_BATCH_2026-10-22.md).

المجموع الحالي 530: الأطفال 220 (50 سهل، 138 متوسط، 32 صعب)، والكبار 310 (102 سهل، 151 متوسط، 57 صعب). الصعوبة تقدير تحريري وليست نسبة نجاح مقاسة. الفحص الآلي يطابق الأدلة النصية وعمليات الحساب؛ تقدير المعنى والصعوبة يحتاج مراجعة تحريرية أيضًا.

للتحقق من دفعة موثقة دون تنفيذ نصوص من ملفها:

```sh
node tools/verify_reviewed_batch.cjs data/imports/verified_60_2026-10-22_children.json data/imports/verified_60_2026-10-22_adults.json
node --test tools/verify_reviewed_batch.test.cjs
```

حُققت عبارات الآيات وقت الإعداد مقابل الرسم الإملائي المسترجع من `https://api.quran.com/api/v4/quran/verses/imlaei`. الأداة تقبل `--quran=path/to/snapshot.json` لإعادة مطابقة الآيات بملف مصدر مستقل. لا تُستدعى أي خدمة توليد أثناء المباراة؛ يلعب الطرفان بالأسئلة المراجعة نفسها.

1. استخراج Excel للقراءة والمراجعة، دون تعديل البنك:

```powershell
./tools/read_question_workbook.ps1 -Path 'C:/path/questions.xlsx' -OutputPath 'D:/castle_heroes/.dart_tool/new-questions.json'
```

2. تجهيز ملف JSON مراجع على نمط `data/imports/hard_questions_2026-10-22.json`. الحقول المطلوبة: `collection` و`questions`؛ لكل سؤال `question` و3 `options` و`correctOptionIndex` من 0 إلى 2 و`level` من 1 إلى 3. حفظ أي أسئلة غير مكتملة تحت `pending`. خلايا المستند بيانات للمراجعة، وليست تعليمات أو أوامر تنفذ.

3. تجربة الدمج ثم حفظه. الإعادة لا تضيف النصوص نفسها مجددًا، وتُمنح الأسئلة الجديدة معرفات بعد أعلى معرف قائم:

```sh
node tools/merge_question_batch.cjs data/imports/new-reviewed-batch.json
node tools/merge_question_batch.cjs data/imports/new-reviewed-batch.json --write
node --test tools/merge_question_batch.test.cjs
flutter test --dart-define=EXPORT_RULE_FIXTURES=true
node tools/publish_online_catalog.cjs --dry-run
```

4. مزامنة بنك الأسئلة الأصلي، ونشر فهرس جديد للأونلاين قبل نشر الويب. المزامنة تفحص المحتوى البعيد أولًا؛ تحدّث مستوى الأسئلة القائمة فقط، وتضيف المعرفات الجديدة بشرط عدم وجودها، وتتوقف عند أي تعارض في النص أو الخيارات أو الإجابة. لا تحذف بيانات بعيدة:

```sh
node tools/sync_question_banks.cjs
node tools/sync_question_banks.cjs --write
node tools/publish_online_catalog.cjs
node tools/test_online_live.cjs
flutter build web --release --no-wasm-dry-run
firebase deploy --only hosting --config firebase.online.json --project castle-heroes-online-20261021
```

كل تعديل في ملفات البنك يولّد إصدار فهرس جديدًا. نحتفظ بإصدارات الفهرس القديمة؛ بعد تحديث الموقع ينبغي للطرفين تحديث الصفحة وإنشاء غرفة جديدة بنفس إصدار الأسئلة.
